# Post-Mortem: Database Schema Mismatch (October 12, 2025)

## What Happened

Flight discovery and tracking tasks were failing with errors like:
```
column flight_logs.max_altitude_agl_feet does not exist
column aircraft.operator does not exist
column flight_positions.ground_elevation_feet does not exist
```

**Impact:**
- 0 flights in database despite tasks running
- All flight discovery tasks failing for multiple days
- Data collection completely blocked

## Root Cause Analysis

### The Five Whys

1. **Why did tasks fail?**
   - Database columns were missing

2. **Why were columns missing?**
   - Alembic migrations were never applied to the database

3. **Why weren't migrations applied?**
   - No automated process to apply migrations
   - `alembic upgrade head` was never run

4. **Why wasn't this detected earlier?**
   - No automated schema validation
   - `alembic check` command exists but wasn't used
   - No CI/CD checks
   - No pre-commit hooks
   - No integration tests

5. **Why were there no automated checks?**
   - Development process didn't include schema validation
   - Assumed manual SQL changes or model changes would "just work"

### The Discovery
```bash

```

**This command existed all along and immediately detected the problem!**

### The Actual Problem

1. **Migrations existed** with all required columns:
```bash
$ alembic history | grep -E "AGL|operator"
fee285f9cbbc -> Add altitude AGL columns to flight_logs ✅
create_abnormal_patterns -> Add AGL altitude and ground elevation columns ✅
e9e85a9bf3fd -> Add operator field to aircraft table ✅
```

2. **But alembic_version table didn't exist:**
```sql
SELECT EXISTS (
   SELECT FROM information_schema.tables
   WHERE table_name = 'alembic_version'
);
-- Result: false
```

**Alembic had NEVER run on this database!**

3. **Database was created some other way:**
   - Direct SQLAlchemy table creation, OR
   - Manual SQL scripts, OR
   - Old migration system

## What Went Wrong

### 1. No Alembic Initialization
```bash
# This was never run:
alembic upgrade head
```

### 2. No Automated Validation
- ❌ No pre-commit hooks
- ❌ No CI/CD checks
- ❌ No startup validation
- ❌ No integration tests

### 3. Bad Migration Generation
The initial migration (`e9e85a9bf3fd`) tried to:
```python
op.alter_column('flight_logs', 'data_source',
    existing_type=sa.VARCHAR(length=50),
    type_=sa.String(length=20),  # SHRINK! Would lose data!
)
```

This breaks with existing data `"flightradar24_complete"` (22 chars).

**Lesson:** Autogenerated migrations need review!

### 4. No Database State Awareness
Models were updated but:
- No migrations created
- Existing migrations not applied
- No checks to detect mismatch

## The Fix

### Immediate Actions (October 12)

1. **Added missing columns manually:**
```sql
ALTER TABLE flight_logs ADD COLUMN max_altitude_agl_feet INTEGER;
ALTER TABLE flight_logs ADD COLUMN min_altitude_agl_feet INTEGER;
ALTER TABLE flight_logs ADD COLUMN avg_altitude_agl_feet INTEGER;
ALTER TABLE aircraft ADD COLUMN operator VARCHAR(100);
ALTER TABLE flight_positions ADD COLUMN ground_elevation_feet INTEGER;
ALTER TABLE flight_positions ADD COLUMN altitude_agl_feet INTEGER;
```

2. **Initialized Alembic tracking:**
```sql
CREATE TABLE alembic_version (
    version_num VARCHAR(32) PRIMARY KEY
);
INSERT INTO alembic_version VALUES ('8740c54ea738');  -- Mark as current
```

3. **Created migration for current state:**
```bash
alembic revision --autogenerate -m "Add missing AGL and operator columns"
alembic upgrade head
```

4. **Verified sync:**
```bash
alembic check
# Output: "No new upgrade operations detected." ✅
```

### Long-term Preventions

#### 1. Created Pre-Commit Hook (`.pre-commit-config.yaml`)
```yaml
- id: alembic-check
  name: Check Alembic Schema Sync
  entry: bash -c 'cd backend && python check_schema.py'
```

**Setup:**
```bash
pip install pre-commit

```

Now every commit checks schema sync automatically!

#### 2. Created CI/CD Pipeline (`.github/workflows/schema-check.yml`)
Runs on every PR and push to main:
- Spins up test database
- Runs migrations
- Verifies sync with `alembic check`
- **Fails the build if out of sync**

#### 3. Created Manual Check Script (`backend/check_schema.py`)
```bash
python backend/check_schema.py
# ✅ Database schema is IN SYNC (revision: 376fc70067b9)
```

#### 4. Created Documentation (`SCHEMA_VALIDATION.md`)
- Complete workflow for model changes

## Recommendations

### For Future Development

1. **ALWAYS create migrations when changing models**
```bash
# After model change:
alembic revision --autogenerate -m "descriptive message"
alembic upgrade head
alembic check  # Verify!
```

2. **ALWAYS review autogenerated migrations**
Look for:
- Accidental column drops
- Type changes that lose data (varchar shrinking)
- Index removals
- Constraint changes

3. **Use the automated tools**
```bash
# Install pre-commit hooks (one time):
pip install pre-commit
pre-commit install

# Every commit now checks schema automatically
```

4. **Add integration tests**
```python
def test_flight_creation_with_all_columns():
    """Test creating flight with all expected columns"""
    flight = create_flight(
        max_altitude_agl_feet=1500,
        operator="Phoenix PD",
        # ... all columns
    )
    assert flight.id is not None
```

5. **Add startup validation (optional)**
```python
@app.on_event("startup")
async def check_schema_on_startup():
    from backend.check_schema import check_schema
    if not check_schema():
        logger.error("Database schema out of sync!")
        # Could fail fast or just warn
```

### For Production Deployments

1. **Always backup before migrations:**
```bash
./scripts/backup_database.sh
alembic upgrade head
alembic check
```

2. **Test migrations on staging first**

3. **Monitor migration execution:**
```bash
alembic upgrade head --sql > migration.sql  # Dry run
cat migration.sql  # Review SQL
alembic upgrade head  # Execute
```

4. **Have rollback plan:**
```bash
# Know how to rollback
alembic downgrade -1
# Or restore from backup
```
